MCUHome packages

This host serves the hash-pinned packages MCUHome tools build against. Each directory below is a self-contained source: it carries its own keys, its own mirror list and its own index, and says nothing about any other directory.

  • /sdk/ — the mcuhome-sdk source package a build compiles from
  • /build-workspace/ — mcuhome-build-workspace, the build environment's source world, the same on every architecture
  • /build-tools/ — mcuhome-build-tools_<os>-<arch>, the build environment's host tools, one package per platform, plus the meta package mcuhome-build-tools that stands for the whole family

Inspect what is published → — every source and version in one table, for looking rather than for installing: that page verifies nothing and cannot, because it is served by the same host it reads. Packages are fetched and checked by the MCUHome tools, which carry a trust anchor of their own. sources.json is the same list as data; it is unsigned discovery only, because nothing above a source has authority.

What a source contains

keys.json      keys.json.sig      the root keys, and the publisher keys they authorise
mirrors.json   mirrors.json.sig   where this source's data may be fetched
index.json     index.json.sig     which file, and which bytes, for every version
<package files>                   plus a .sha256 sidecar for each, and any
                                  further sidecar the build wrote beside it

Everything is signed with Ed25519. The signature covers the exact bytes of the document as served, and the hashes inside the index reach from there to every package file — so a mirror can be untrusted without anything else being.

Meta packages

Some names in an index stand for a set of packages rather than for one file: mcuhome-build-tools is one per platform, and a build that has to run on either architecture pins the family instead of one platform's bytes. Such an entry carries a meta map from each architecture to the concrete package name, and a sha256 derived from those packages' own hashes — so pinning the family still pins exactly what every platform will get. It names no file and no size, because there is nothing to fetch until it has been resolved. A meta package exists at a version exactly when every one of its members does.

Verifying a copy

The reference verifier is a single file. Point it at a source directory you already have and at the root key set you trust:

verify.py sdk/ --anchor anchor.json

It is the executable form of the rule tools follow, and it is the same code the test corpus in the repository is checked against.

Mirroring

A mirror is a copy of a source directory — no path rewriting, no per-mirror layout. Copy the whole directory, serve it over HTTPS under your own name, and it is complete. Mirrors may carry one source and not another. To be listed, open an issue in the repository below.
